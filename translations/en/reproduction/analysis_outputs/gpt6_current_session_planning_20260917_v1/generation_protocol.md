# GPT-6 conversation planning batch protocol

English reading translation of the protocol frozen on 2026-09-17. This document describes that historical batch, not a new generation run.

Task specifications and candidates were directly written by the GPT-6 assistant in the conversation. The model name follows the session identity; no server request IDs, sampling parameters or provider signatures are available. The assistant knew the manuscript method and existing checking code. This is a method-aware, single-conversation candidate-interface study, not a blind test, external human gold standard or independent API benchmark.

The user requested generation of task plans followed by statistical analysis. The batch size was fixed at 24 tasks, four in each of six domains. Tasks use distinct operations and dependency structures; candidates were not obtained from the four existing templates or by random edge deletion. Specifications were saved first, all candidates were then written and frozen, and evaluation followed. Each task retains one first-round candidate. Errors were not injected to create apparent repair gains; failed samples were not removed and candidates were not edited after evaluation. No synthetic random seed or repeated independent model sampling is claimed.

Nodes contain exactly id, action, object, Pre, Post, d, Res, Cand and mode. Original edges are saved explicitly as E_state/E_sync triples, E_mutex resource triples and E_order node pairs. The adapter only maps field names and L/R/B labels; it does not infer, add or remove relations. Durations are manually/model-assigned integer symbolic time units representing input estimates, not device measurements. L/R are two abstract base units, and B occupies both simultaneously. States are represented process facts without delete effects; all resources have capacity one.

Predefined statistics comprise parsing/raw-schema pass rates; the six individual checks and joint acceptance before/after repair; closure rate; goal reachability; static parallelizable node pairs; accepted/rejected edits and stage distributions; strict schedule acceptance; exported-interval checks; and replay agreement using complete labelled edge keys. Only actually accepted strict schedules contribute symbolic makespan, total busy occupancy, utilization and same-node serial-time/current-time speedup. The same raw candidate is also compared under the full method and disabled order compression, restricted to jointly accepted tasks. Without an independent reference graph, node/edge/parallel precision, recall, F1 and semantic accuracy are not computed. Post-processing outputs are not treated as gold standards.

The existing implementation version is fixed, with code copies/hashes and all raw inputs, candidates, repaired graphs, logs, schedules and per-record results saved. Any input defect found after candidate evaluation is recorded only as a diagnostic. This historical batch did not modify the existing manuscript, code or earlier experiments. Means, sample standard deviations, medians and ranges describe this batch, without population inference or significance testing. Failure rates are record proportions under the batch conditions.
